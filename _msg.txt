feat: 能力对齐 —— 修复空回复根因、tools 缓存断点、environment 段、并发限流

基准测试从 2/3 提升到 3/3（首次全绿）。同时推翻了一条既有结论。

## ① 空回复的真实成因（最重要，能力级）

基准里出现「HTTP 200 但可见内容为空」。同一问题、同一模型直接复现：

    max_tokens=512   → content 0 字符    finish_reason=length  ← 空回复
                        reasoning_content 1747 字符
    max_tokens=4096  → content 122 字符  finish_reason=stop    ← 正确回答

机制：
- 实测确认，不传 thinking 字段，上游照样返回 reasoning_content
  —— GLM-5.3 在 start-plan 通道上默认启用扩展思考
- 思考与可见输出共享同一个 max_tokens 预算
- 调用方传 512/1024 这类偏小值时，只够思考、不够回答

这不是模型能力问题（同题预算够时答案正确），但表现出来就是
「模型变笨了/答非所问/回空」。不查到这一层，很容易往换模型、
加提示词方向瞎修。

修：adapter.ts 加 MIN_VISIBLE_BUDGET = 4096 预算下限
    （ZCODE_BRIDGE_NO_BUDGET_FLOOR=1 可关，供对照）

## ② tools 缺 cache_control（性能）

dump 实测：system 三块全带 cache_control，而 24 个工具、19492 字节
零个缓存断点。

Anthropic 的 prompt caching 是前缀式的 —— 在最后一个 tool 上打一个
断点即可覆盖「system + 全部 tools」，不必逐个打。

修：cacheableTools，只给最后一个 tool 加 cache_control

⚠ 影响评估属推测：用 ttftMs 从 1.3s 飙到 25s 而 mintMs 稳定 200-700ms
  作为间接证据指向冷缓存 prefill，未做 A/B 坐实。但官方客户端本就带 cc。

## ③ environment 段从未发送（能力级）

OFFICIAL_ENVIRONMENT_LABELS 早已定义却一次都没被引用。
实测：问「你是什么模型」只能答出笼统的 GLM。

修：新增 buildEnvironmentSection()。现在实际发出 cwd / 是否 git /
    平台 / shell / OS 版本 / 自身型号。

踩坑：Electron utilityProcess 里 os.release() 返回 win32
      （纯 Node 下返回 10.0.26200）。已改为多级回退，
      优先用 Electron 专有的 process.getSystemVersion()。

## ④ 默认模型 Flash → GLM-5.3（配置）

全天 639 次请求 607 次 Flash（95%），07-16 点零次 GLM-5.3。
根因是 profile 硬编码（非 product.ts）。

⚠⚠ 但要诚实说明：同负载 A/B（各 5 轮 × 3 题，交替执行）显示

    GLM-5.3        n=14   中位 4452ms   正确 8/14  (57%)
    GLM-5.3-Flash  n=15   中位 4915ms   正确 10/15 (67%)

GLM-5.3 略快但略不准 —— 推翻了本项目此前的结论。
具体：简单算术题 GLM-5.3 多次答 12（正确 6）；
     等字数反义句它答「曾经宕机」（存在量化，不是「从未」的反义）。

边界：n≈15 样本量小，差异可能不具统计显著性。但至少可确定
      没有证据支持 GLM-5.3 明显更强。默认模型该选哪个建议按
      实际感受定，不要照搬历史结论。

## ⑤ code:3009 并发限流（稳定性）

完整拒绝体：{"code":3009,"msg":"model concurrency limit exceeded"}
token 额度还剩 299.4 万 ⇒ 是并发配额，不是 token 配额。

按模型统计（全天）：
    GLM-5.3-Flash  605 次 200    0 次限流   ← 从未撞过
    GLM-5.3         74 次 200   21 次重试    6 次最终 429

⇒ GLM-5.3 有独立且更严格的并发配额。

修：串行闸门（只包 fetch）+ 按模型自适应最小间隔
    （Flash 0ms / GLM-5.3 350ms）+ 重试 2 次（1500ms 起退避）
    + 重试前重新 mint（captcha 一次性，复用必然失败）
效果：3009 从 21 次降到 1 次

## ⑥ 附带：修掉 switch 的 toggle.checked

model-toggles.ts 里写 toggle.checked，但元素是 button role=switch，
没有 checked 属性 —— 类型上过不了，运行时是静默挂无效 expando，
UI 根本不会回弹。已改为 aria-checked。
