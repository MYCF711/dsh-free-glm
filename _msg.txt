## 一、视觉编辑器（builder.html）

### (1) Tab 切换时下面的内容不跟着换（用户报）

根因：tabbar 只渲染自己（下划线会动），但没有任何机制去控制
下面的内容区 —— 两者是完全独立的两块。

新增 tabpanel 组件，用 bind 属性与 tabbar 关联：

    tabbar    bind="t1"        ->  tabState["tab:t1"] = 0|1
    tabpanel  bind="t1" idx=0  ->  仅当 idx 匹配时显示
    tabpanel  bind="t1" idx=1  ->  仅当 idx 匹配时显示

renderEl 每次重绘都重跑，状态一变面板自动显隐，无需事件订阅。

真实浏览器验证（headless Edge + CDP 真实鼠标事件）：
点击「账号管理」-> 面板 e6 -> e10，下划线 idx 0 -> 1，
内容变成 "mylzscy4 正常 3.0M"。

### (2) 容器太小，拖不进去（用户报）

「只能插在容器的上方或者下方」的根因是两处叠加：

- .rowbox 只有 min-height:32px + padding:2px，虚线框内实际约 28px
- 落进容器要求精确命中虚线框（正负 0.5px）

改：
- min-height 32 到 56px、padding 2 到 8px、.r-panel 34px
- 容器命中加 CONTAINER_PAD = 12px 外扩
- 拖拽中给所有容器加高亮（body.dragging），让"能放哪"可见
- 空容器占位符撑满（flex:1），容器内任何位置都能接住

实测（真实布局）：.rowbox 56px 高；可命中面积 19% 到 28%（外扩生效）。

### (3) Tab 需要绑定容器，应默认给（用户报）

「tab 肯定是需要一个绑定的容器，设置成默认的」。

原来拖一个裸 tabbar 进来是不可用的 —— 它只有下划线，
点了下面什么都不换。要能用必须再拖 N 个 panel 并逐个设属性，
这是把实现细节暴露成操作负担。

改：拖入 tabbar 时自动按项数创建面板，bind 指向该 tabbar，
idx 依次 0..N-1。初始卡片也改成同样的结构。

另外：空面板现在标明所属 Tab（「模型 面板 · 把内容拖进来」），
否则两个空面板长得一样、用户不知道哪个是哪个。
绑不到时明确写出原因与修法，而不是静默退回通用提示。

## 二、脱壳可行性（用户提出「captcha 用别的浏览器也行」）

### 实测结论：captcha 不需要 ZCode 壳，但必须是 Electron

同一脚本、同一页面、同一网络，只换浏览器：

- ZCode 实例（ZCodeDev/41.0.3 Electron/41）：ok=true
- 最小 Electron（零 ZCode 代码）：ok=true
- headless Edge 154（HeadlessChrome）：F001 失败

判据是 Electron 内核，不是 ZCode 这个具体应用。
未单独测「有头 Edge」—— 只证明 Edge 无头失败、Electron 成功。

### 收尾验证：param 真的被上游接受

独立产出的 param + 官方身份块 + JWT，绕开桥直打上游：

    POST https://zcode.z.ai/api/v1/zcode-plan/anthropic/v1/messages
    -> HTTP 200  3180ms  model=glm-5.3-flash

脱壳路径打通。但当前架构仍可用且稳定，脱壳是"可以做"
而非"必须做" —— 价值在减少依赖，不是解决故障。
未做：常驻化、预热池、并发与失败重试。
